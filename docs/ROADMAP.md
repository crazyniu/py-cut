# 开发路线图（ROADMAP）

> 状态约定：**规划中**（未实现）/ **进行中** / **已实现**。
> 当前仅 `slice` 已实现。以下为后续功能的规划记录，开发时再细化。

---

## 已实现

### ✅ slice —— 智能切片 + 人脸分流 + 字幕擦除
- 场景分段（ffmpeg scene 分数，最短段 ≥2s）
- 人脸三态判定（Haar 分筛 + LLM 兜底），按有人脸/无人脸分目录
- 字幕真实擦除（文字掩膜 + TELEA 修复，非毛玻璃）
- 幂等标记、CSV/JSON 双写清单
- 入口：`pycut.py slice` / `cover`

---

## 规划中

### 1. montage —— 混剪视频
**需求**：用户提供一段"爆款音频"（如时长 60s），工具根据音频时长，从已切好的切片中
挑选并拼接，自动混剪出一段与音频等长的视频。

**要点（待细化）**：
- 输入：音频文件路径（或目录）；音频时长决定总时长目标。
- 切片来源：复用 `slice` 产出的 `~/Desktop/切片_有人脸` / `切片_无人脸`（或指定桶）。
- 选片策略：按音频节奏/节拍点对齐切点（可选 beat 检测）；人脸/无人脸偏好；避免连续重复镜头。
- 拼接：ffmpeg concat；统一分辨率/帧率；音画对齐。
- 与 slice 的关系：montage 是**下游消费方**，不重新切片。

### 2. transition —— 转场贴纸（婚礼视频场景）
**需求**：在婚礼视频的切片之间增加**转场贴纸**（如爱心、闪粉、相框等动态贴纸），
提升成片观感。

**要点（待细化）**：
- 在 montage 拼接的接缝处插入转场（淡入淡出 / 滑入 / 贴纸动画）。
- 贴纸资源：内置若干 PNG/WebM 贴纸，或支持用户自定义目录。
- 婚礼场景可能需要更柔和的转场与暖色调。

### 3. dedup —— 过平台查重
**需求**：对每一个切片做处理，使其能通过抖音/视频号等平台的**查重机制**（重复内容限流/下架）。

**要点（待细化）**：
- 采用"已知的查重方案"——需先调研各平台查重算法（关键帧哈希 / 视频指纹 / MD5 分块等）。
- 常用对抗手段（需评估合规性，仅用于自有素材去重）：
  - 画面层：随机轻微缩放/位移/旋转、加噪/调色、叠加水印或贴纸、抽帧率微调。
  - 编码层：变更 GOP/关键帧间隔、码率浮动、编码参数扰动。
  - 结构层：镜头顺序打乱、片头片尾差异化。
- 注意：**不要触碰九源仙·苍耳子油鼻舒喷雾项目的红线——禁止任何功效/医疗宣称**，查重处理仅作用于画面技术层，不改变文案语义。

### 4. quality high —— AI 级字幕修复（可选）
**需求**：当前 `subtitle.cover_clip` 用经典 TELEA 修复，大号艺术标题字形内部偏平滑。
提供 `--quality high` 走 AI 视频修复模型（ProPainter / LaMa）做到无痕，代价是速度慢约百倍。
**要点**：作为 slice/cover 的可选模式，默认仍用快速经典算法。

## 设计原则（贯穿后续）

- 所有新功能以**子命令**挂载到 `pycut.py` 入口，复用 `core/` 成熟能力，不重复造轮子。
- 目录按职责拆分，保持长期可维护（见 `Agent.md` 与 `README.md`）。
- 涉及 LLM 的视觉/文本能力统一走 `core/llm.py`。
- 涉及 ffmpeg 的封装统一走 `core/ffmpeg.py` + `core/slice_pipeline.cut_clip`。
